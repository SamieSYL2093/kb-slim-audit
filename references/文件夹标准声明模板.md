# 文件夹标准声明模板（kbstd 四型）

> 用途：给目录声明文件夹标准时的**抄写样板**。机制定义见 `SKILL.md` S11/S13 节。
> 原则（用户 08-29 定）：
> ① **没有定制就空缺**——一行 R0 引用就是合法声明，不要为填而填；
> ② **只标准化能标准化的**——格式与机制统一，**值是各项目自己的事**，本模板所有值都是占位符；
> ③ kbstd 每个字段都是**覆盖项**，没写的字段 = 继承全局默认（X-NN）。

## 型一：普通文档仓（无定制）——"空缺"形态

没有特殊需求的目录，**不需要 kbstd 行**。在 AGENTS.md 放一行 R0 指针即可（照抄）：

```
全局文件夹规范见总仓 `X-NN`（唯一事实源）。本仓遵循其第一节四条理念：**① 第一层有规范 ② 层级 <3 ③ 命名具体不笼统 ④ 归属唯一**（单一事实来源属知识管理原则，见 `X-NN` #1）；细节冲突以本仓细则为准。
```

> 效果：S13 缺标准不报，S11 按全局默认（层级 <3）查。**这就够了，别多写。**

## 型二：有定制的目录——只写覆盖项

在本目录的 AGENTS.md / README.md 加一行（HTML 注释，渲染不可见）：

```
<!-- kbstd: max-depth=<数字|none> reason=<一句话：为什么这个目录需要例外> -->
```

- `max-depth` 不写 = 继承全局默认；只写你要覆盖的字段
- `reason` **必填**——没有理由的例外是耍流氓，理由是给下个 AI 看的

## 型三：代码工程

```
<!-- kbstd: max-depth=none reason=AI编程项目，目录结构由框架生态决定 -->
```

> X-NN 是文档管理规则，压不动也不该压代码树（src/components/… 的深度是框架定的）。

## 型四：快照 / 归档 / 镜像

```
<!-- kbstd: max-depth=none reason=快照原样保留他处结构 -->
```

> 实例：P35 `AI记忆资料库`（全库第一个声明，2026-08-29）。

---

## 防呆

- **一目录一行**，写在离内容最近的 AGENTS.md / README.md；多层声明时**最近的生效**
- 声明只影响**本目录及子孙**；兄弟目录各声明各的
- 改标准 = 改这一行 + 署名 commit；删行 = 回到继承
- 拿不准该不该定制：**不定制**（空缺失继承永远是对的，定制错了才是债）
