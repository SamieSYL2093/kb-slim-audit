# 示例：一次真实审查的输出（脱敏）

> 本文件不是模板（AI 会自己组织输出），是一次真实审查的**效果示例**：看这套方法用在真实场景能挖出什么。
> 真实场景：某多 AI 协作的知识库，22 个目录、183 个 Markdown 文件。已脱敏，内部编号与路径已泛化。

## 瘦身审查（范围：22 个目录 / 183 个文件，根 + 一级层）

### 已修复（审查过程中发现的明确缺陷）

| 发现 | 修复 |
|------|------|
| 规则表宣称有「AGENTS 指针一致性」检查，但校验脚本里**根本没实现**——宣称的规则是空的 | 补实现，上线首跑即抓到 4 个目录的指针过时（写"五条理念"，总纲已改四条） |
| 总纲文件尾部指向**已删除的章节** | 改指现存的章节 |

> 教训：**删章节前先 grep 下游引用**。断链比冗余更伤。

### 待拍板（只报不动）

**可删除 / 合并：**

- [移] `模拟系统-V1.md` + `模拟系统-kimi.md`：同一需求的三份（正式版已到 V14）→ 前两份是早期残留，归档或删
- [并] `立项-初稿.md` + `立项-工单版.md`：同一立项两份，内容互补（初稿有决策路径与关闭条件，工单版有分工边界）→ 合并为一份
- [移] `【文章】XXX完整修复指南.md`：对外发表成品，与内部实录同源 → 按放对层移发表仓

**可压缩 / 单源化：**

- [压] `README.md`（65 行）：简介段、状态表、输出方向三处与总览文档双写 → 只留导航表（65→27 行）
- [转] `题库-新增724.md`（1776 行纯数据当 MD 存）→ 转 JSON；随机抽验确认数据已在系统里后删除 MD
- [单源] `分发稿-skill.md` vs `SKILL.md`：同一课程双份维护，改了本体分发稿不跟 → 分发稿改为从本体生成
- [补] `某项目/`：挂着"待办：缺 README"没人做 → 补建最小 README

### 查过不动（防误删备忘）

| 位置 | 看似问题 | 实际判断 |
|------|---------|---------|
| 骨架 `README.md` vs `README模板.md` | 疑似重复 | 职责不同：一个说明用法，一个是填充模板 |
| 两个平台的 `_auto_publish_使用说明.md` | 疑似重复 | 不同平台不同脚本 |
| 各仓 `AGENTS.md`（6-7 行） | 命中 4 个总纲关键词 | 标准指针写法，命中是正常的 |
| 实录类文档 | 多个大文件 | 历史档案，不动 |

## 结果

- 7 项结论全部可执行，修复后复跑校验脚本 **0 问题**
- 报告里"查过不动"6 条，避免后续重复审查
- 处置耗时：审查约 40 分钟，执行约 20 分钟（跨 5 个仓库提交）
